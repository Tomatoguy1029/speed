# ステージ制作ガイド

ステージの仕様と敵・ボスの仮実装を受け取り、**配置する → 動きを確かめる → 数値を調整する → 通しで遊ぶ**ための案内。まず担当する工程を読み、細かい操作や原因調査は[AI向け資料](stage-production-ai.md)を読ませたAIに質問する。

たとえば「中盤の強敵が多すぎる」と感じたら、対象クリップの `Group counts` を確認し、その区間を再生する。通しの成長も変わったかは、保存後に先頭から録画して比べる。敵の強さを変えたい場合は、[F4](#51-f4でステージ内の敵数値を試す)でそのステージの値を試す。

|---|---|
| [1. 仕様と担当範囲を確認](#1-仕様を確認して開く) | 何を目指し、どこまで変更するか |
| [2. 配置と編成を作る](#2-タイムラインを触る) | 時間帯・出現数・並び・候補・重み |
| [3. 成長の流れを作る](#3-フェーズの狙いを配置にする) | 育成区間とボス前の完成度 |
| [4. 敵・ボスの狙いを決める](#4-敵とボスを設計する) | 脅威、避け方、攻めどき |
| [5. 単体確認と数値調整](#5-敵の動きと見た目を仕上げる) | 実験場・F4・敵ドック・ボス編集の入口 |
| [6. 録画してAIと改善](#6-記録と感想で調整する) | 分析、相談、変更、再プレイ |

## 1. 仕様を確認して開く

担当ステージの仕様でコンセプト・登場敵・フェーズ・成長目標・ボスを確認する。例は[ステージ4](../game/stages/stage-4.md)。目標が未設定なら、調整前に本人と決める。仮目標は仮のまま比較に使う。

[READMEの起動方法](../../README.md#godot-で開発する)でGodotを開き、`res://data/stages/stage_4.tres` など担当ステージを選ぶ。F5から通常のステージ選択で今の状態を遊ぶ。以降の `res://` はGodotプロジェクトの `speed/` 内を指す。

**基礎担当は共通の基準、ステージ制作担当は担当ステージの配置・上書きを調整する。** 共通XP・機体強化幅・共通敵定義に関わる課題は基礎担当へ相談する。共有している編成・時間帯を変えると他ステージにも影響するので、編集前に参照先を確認する。

## 2. タイムラインを触る

### 2.1 開く・時間を配置する

ステージの `.tres` を選び、下部「出現タイムライン」か上部の同名タブを開く。

| 作るもの | 最初の操作 |
|---|---|
| フェーズ（時間帯） | 区間をクリックして内容を開く。境目をドラッグして時刻を変え、右クリックで追加・削除・名称変更・強化区間を設定する |
| 雑魚の数 | 上段「雑魚敵」で種類を追加。曲線をダブルクリックして点を置き、ドラッグして「その時刻にいてほしい数」を変える |
| 強敵の区間 | 上段「強敵」でトラックを追加し、空き部分をダブルクリックしてクリップを置く。棒で開始位置、右端で長さを変える |
| ボス・終了時刻 | 目盛りで位置を選び、上段「ボス」「終了」でピンを置く。ドラッグで移動する |

### 2.2 クリップに編成を登録し、使う候補を選ぶ

1. ステージの `Enemies` で使う敵をONにする。
2. クリップを選び、`Types` で出す敵を選ぶ。
3. `Spawn assets` →「＋ Spawn asset」で `data/formations/*.tscn` を登録する。
4. `Formations` の「使用」で出す並びを選ぶ。
5. `Group counts` に残しておきたい群れ数、`Interval` に補充の最短間隔を入れる。

**シーンの登録と、並びの使用選択は別。** 1群れの体数は並びによって変わる。敵が1体でも残る群れは残存群れとして数える。

### 2.3 編成シーンで並び・出現位置・重みを作る

`Spawn assets` のシーンを開き、2D画面で編集する。ステージ専用に変える場合は別名で保存し、クリップの参照を差し替える。

| 選ぶノード | 編集すること |
|---|---|
| 根の `EnemyFormation` | `Types` で配置する敵を指定 |
| 子の `FormationLayout` | 並びの候補。複製して増やし、`Weight` で選ばれやすさを設定 |
| 並びの子の `FormationMarker` | `Enemy` と位置・向き。マーカー1つが敵1体 |
| 根の子の `FormationEntry` | 機体に対する出現位置。複製して候補を増やし、`Weight` を設定 |

保存後、クリップへ戻って `Formations` の「使用」を確認する。**`Weight` は候補を選ぶ比率**。出現量や攻撃待ちの優先度とは別の設定になる。

### 2.4 編成のプレビューを確認する

根の `Preview Layout`・`Preview Entry` を切り替え、並びと出現位置を重ねて確認する。画面の目安枠と赤い配置警告を見て、間隔・向き・画面への入り方を確かめる。使用する並びはプレビュー番号ではなく、クリップの「使用」で選ぶ。

### 2.5 出現量と攻撃の重なりを調整する

| 変えたいこと | 編集するもの |
|---|---|
| 敵を増減する・補充を変える | 雑魚の曲線、`Group counts`・`Interval`・区間・マーカー数 |
| 並びや出現方向の比率を変える | `FormationLayout`・`FormationEntry` の `Weight` |
| 同時攻撃の重なりを変える | 時間帯の「予算」、種類ごとの `Enemy attack values` |
| 群れで攻撃予算を共有する | `Formations` の `Auto` を目安に `Override` を設定 |
| 攻撃待ちの順を変える | クリップの `Attack Priority`、ステージの `Enemy attack priorities` |

詳細や操作例は[AI向けの配置・編成手順](stage-production-ai.md#タイムラインの操作と編成制作)を使う。

### 2.6 保存・警告・再生を確認する

タイムラインは編集確定・取り消し時に自動保存する。編成シーンはシーンとして保存する。赤枠のクリップを選ぶか「ルール違反のクリップ」→「詳細」で問題を読み、敵・種類・シーンの登録を修正する。

目盛りで確認位置を選び「再生」すると、その区間を試せる。F5・F6・途中再生の開始前に実行用データを生成し、失敗すると起動を中止する。Godotの出力を確認して修正する。

**途中再生は配置や挙動の確認用。通しで成長した状態との比較は先頭から遊ぶ。**

## 3. フェーズの狙いを配置にする

ボス前にどの程度装備を完成させたいかを起点に、育成区間・選択ペース・到達レベルを考える。目標の正本は担当ステージの仕様に置く（[ステージ4の例](../game/stages/stage-4.md#2-フェーズと成長目標)）。

### 構成・調整のtips

| 狙い・困りごと | 配置と試遊で見ること |
|---|---|
| 育成区間で経験値を稼がせる | **そのステージで経験値供給を担う敵を厚くする。** [ステージ4](../game/stages/stage-4.md#2-フェーズと成長目標)では分裂する雑魚を多めに出し、分裂体までまとめて処理する。[ステージ3](../game/stages/stage-3.md#成長の方針)は猟犬の群れを倒して稼ぐ。担当ステージの方針を使う |
| 同じ密度が続いて単調 | 同じフェーズ内でも雑魚の曲線に山と間を作る。ステージ4では噛みつく雑魚を増減させ、押し寄せる群れと駆け抜けたあとの余裕を作る |
| 育てた強さを使わせる | 育成で得た力を山・ラッシュで使える構成にする。例は[ステージ4のコンセプト](../game/stages/stage-4.md#1-狙う体験)。敵の数だけでなく、まとめて倒せる並びや攻める経路も見る |
| 混成にすると厳しすぎる | 強敵は単体で確認してから組み合わせる。数・配置が作る圧力と、攻撃予算が作る同時攻撃の重なりを分けて調整する |
| 育成なのに伸びを感じない | 倒せる数・落ちるXP・拾える量を分けて見る。出現数を変える前に、どこが詰まっているかを[録画分析](#6-記録と感想で調整する)で相談する |

分裂する敵の増量を全ステージの共通ルールにはしない。敵の役割と具体的な目標は各ステージ仕様を参照し、数や補充間隔は試遊で調整する。

## 4. 敵とボスを設計する

モチーフの形と動きから「どう脅かし、高速移動や突進でどう切り抜け、どこを攻めると気持ちよいか」を決める。[敵設計の6分類](../game/catalog/enemies.md#敵設計の6分類)で攻撃を見渡し、同じ避け方ばかりになる偏りを確認する。

予兆→狙い固定→攻撃→停止までを一続きで作る。大技には進路・順番・攻める位置を選ぶ理由を持たせ、攻撃後の頭や敵の配置を反撃の経路にする。具体例は[ヒュドラの仕様](../game/bosses/hydra.md#1-狙う体験と攻撃の整理)、詳しい検討順は[AI向けの設計手順](stage-production-ai.md#敵ボスの設計を支援する)を使う。

## 5. 敵の動きと見た目を仕上げる

予兆や攻撃範囲の読みやすさ、見た目と当たり判定の一致、回避後の攻めどきを確認する。絵・演出の差し替え先は[AI向けの編集先一覧](stage-production-ai.md#編集先を選ぶ)から辿れる。

### 実験場で単体の動きを確認する

Godotの「プロジェクト → ツール → 実験場」（または上部「▶ 実験場」）を開く。「試遊対象」には登録済みの通常敵・強敵・分裂体・召喚体・ボスが並ぶ。対象を選んで「試遊」し、ボスは「ボス技」から技を選んで即実行できる。「自由配置」では従来の敵配置とルート編集を使う。

画面上部の「ヒットストップ」は選択中の試遊対象に連動する。0は停止なし、1は従来の共通時間。試遊中の変更は現在の同種と次の出現に反映する。「敵種類の定義（全ステージ）」または「このステージのみ」を選び、「設定を保存」を押した時だけ元データへ保存する。ステージ設定は「ステージ設定を継承へ戻す」で解除できる。「試遊値を戻す」や実験のリセットは保存を行わない。ボスの保存先はボス定義だけで、ステージ上書きは選べない。

数値変更はその実験内に適用し、「保存」は実験用JSONを残す。**現在はステージ選択だけでは保存済みの敵上書きを再現しない。** ステージ固有値は本番ランで確認する。

外観の「この種類の設定をステージへ保存」は、現実装では共通の外観データへ保存し、全ステージに影響する。戦闘値のステージ保存とは分けて扱う。[保存先と制限の詳細](stage-production-ai.md#実験場の操作と保存範囲)を確認する。

### 5.1 F4でステージ内の敵数値を試す

1. F5で担当ステージを遊び、ゲーム画面でF4を押す。
2. 「ステージ敵調整」で敵を選び、分類・検索で項目を探す。
3. 「共通値（参照）」を見て、「このステージで上書き」をONにして値を変える。
4. 動きを確かめ、残す場合は「Save」。試行を捨てる場合は「再読込」。

標準HP・装甲・速度・加速・旋回・弱点角度・ヒットストップ時間倍率と、敵ごとの数値を調整できる。変更は既存の通常敵にも反映し、残HP割合や現在の行動を保つ。発射済み攻撃はそのままなので、次の行動でも確かめる。パネルを開いてもゲームは止まらず、閉じても未保存の試行値は残る。

### 5.2 共通値・ライブ反映・保存を区別する

**ステージ上書きがある項目はその値、ない項目は共通デフォルトを使う。** 速度だけを上書きすれば、発射間隔など別の項目は共通値へ追従する。共通変更は、その項目を上書きしていないステージへ広がる。

たとえば共通の速度を変えても、速度を上書きしたステージは指定値を保つ。「上書きを解除」すると、その時点の共通値へ戻る。共通値と同じ数を上書き保存した状態は固定値なので、解除とは異なる。[具体的な数値例と反映の確認](stage-production-ai.md#共通値とステージ上書きの具体例)を参照する。

### 5.3 保存・戻す・エディターで編集する

| 場所 | 保存と戻し方 |
|---|---|
| プレイ中のF4 | 「Save」で担当ステージへ保存。「↶」やチェックOFFで項目を解除。「再読込」で未保存試行を破棄 |
| エディター右側「ステージ敵調整」 | 担当ステージ→「敵」→「分類」→項目の順に選び、「上書きする」で編集。「保存」で確定、「解除」で共通値へ戻す |
| 共通の敵定義 | `res://data/enemies/` の対象 `.tres` をインスペクターで開く。共通値の変更は基礎担当の範囲 |

ヒットストップの試遊・保存は実験場でも完結する。項目名は `hitstop_multiplier`。停止条件・倍率の意味・上限は[ヒットストップの仕様](../spec.md#74-ヒットストップ)を参照する。敵の全ステージ共通値は `data/enemies/<type ID>.tres`、ステージ固有値は `StageDef.enemy_tuning`、ボス本体の共通値は `data/bosses/<boss ID>.tres` に保存する。

ドックがなければ、プロジェクト設定→プラグインの `Stage Enemy Tuning` を確認する。保存先は担当ステージの `enemy_tuning`。保存・生成の成功を確認し、F5で起動し直す。競合や生成失敗が表示されたら、内容を確認してから再試行する。[詳しい保存・解除・競合対処](stage-production-ai.md#f4と敵ドックの操作保存)を使う。

### 5.4 ボスの編集先を確認する

うみへび座・いっかくじゅう座・りゅう座は[ボスAI画面](#55-ボスaiを調整する)で編集する。ボスごとの仕様と公開項目を確認する。

既存F4のステージ上書きはボス本体・技の設定を対象に含めない。[参照先と確認方法](stage-production-ai.md#ボスの区間フロー攻撃値タイムライン)で、編集元から実行までの対応を確認する。

### 5.5 ボスAIを調整する

Godot上部「ボスAI」、メニュー「プロジェクト → ツール → ボスAI」、またはCmd/Ctrl＋Alt＋Bで開く。左上でうみへび座・いっかくじゅう座・りゅう座を選ぶ。表示されなければプラグイン「ボスAI」を確認する。

#### ノードで調整すること・実装を依頼すること

**戦闘の組み立てはノード、技の動作とボス全体の固有制御はスクリプトで作る。** ボス固有の技も、実装済みの動作と公開された調整項目を使う範囲なら、この画面で編集できる。

| 担当すること | 編集する場所 | 調整・制作の例 |
|---|---|---|
| 戦闘の大きな流れ | 上段の区間ノード、スタミナ・休息 | 区間ごとの使用可能な技・選択割合・消費上限・同時攻撃の禁止、次の区間とループ、休息時間 |
| 技を候補にする条件と整理 | 条件選択ノード、技への接続条件 | プレイヤーとの距離・方向、候補の有効／無効、技のグループ分け。発動条件は技ノードを選んでも編集できる |
| 技の性能 | 技ノード | ダメージ・攻撃範囲・消費量・技後の待ちなど、その技が公開する値。竜の吸引吐出では複数の弧の追加・削除・位置・半径・角度・弾数、螺旋収縮では半径と体・頭のサイズを調整する |
| 既存技の組み合わせ | コンボ内部 | 順番に出す、同時に出す、間を空ける、距離・方向で次の技を変える |
| 技ごとの制御 | スクリプトの実装を依頼する | 新しい突進軌道、弾道、照準方法、攻撃判定、新しい相乗効果、技固有の成立・中断処理 |
| ボス全体の固有制御 | スクリプトの実装を依頼する | 形態移行、部位の破壊・再生、分離、護衛、複数個体の位置調整 |

区間は「この区間ではどんな攻撃を選ぶか」と次の区間を決める。選んだ攻撃と技後の待ちが終わると次へ進む。下段の技定義を複数の区間から参照するため、同じ技の性能変更は、その技を使う区間すべてに反映される。

例えば「既存の射撃を2回続ける」はコンボ編集で組める。「弾が壁で反射するようにする」は、その動作が実装されていれば公開値を調整し、未実装ならスクリプトの追加を依頼する。同様に「渦と雷を同時に出す」は既存技の併用が成立すれば組めるが、「雷が渦を伝わって別の攻撃へ変化する」には、その相乗効果の実装が必要になる。

任意の技を同時に動かせるかは、各技の実行制約による。移動や照準を共有する1体のボスなどは、同時に使える組み合わせを実装側で確認する。また、新しい条件（例：プレイヤーが突進中）や画面にない調整項目を使いたいときも、判定と項目の追加を依頼する。

実装を依頼するときは、**対象ボス・技、開始条件、予告から攻撃終了までの動き、中断時の扱い、ノードで調整したい値**を伝える。スクリプトの場所・情報の流れ・追加手順は[AI向けの実装案内](stage-production-ai.md#スクリプトの入口と追加実装の判断)を参照させる。

#### 実装した技を画面で使うまで

**技の動作を実装する → 技の設定ファイルを作る → ボスの技一覧へ登録する → 技ノードを選んで調整する**、の順で進める。

登録先は `res://data/bosses/ai/<boss>_action_rules.tres` の **`techniques`**。海蛇は `hydra_action_rules.tres`、一角獣は `monoceros_action_rules.tres`、竜は `draco_action_rules.tres` を使う。ここへ `res://data/bosses/<boss>_moves/` に作った技の設定ファイルを登録すると、ボスAI画面の読込時に技ノードが表示される。スクリプトと設定ファイルの作成・登録までを実装担当へ依頼する。

調整担当は、未保存の編集を保存し、登録内容を読み込み直して技ノードを選ぶ。そこで発動条件・性能・消費スタミナを調整し、使用する区間の「この区間で使える技」に加えて試遊する。条件選択の所属は「技の接続先を変更」で整理できる。区間が「全技を候補にする」の場合は、新しい技も選択対象に入る。

技ノードは登録済み一覧から表示される。画面上の「コンボ技を作成」は既存技を組み合わせる操作で、スクリプトから新しい動作を登録する工程は[AI向けの登録手順](stage-production-ai.md#技を登録して技ノードへ表示する)を使う。

#### まず選ぶ場所

| 場所 | 目的と最低限の操作 |
|---|---|
| 上段「戦闘の区間」 | 青い区間を選び、右側で「要求する攻撃」「この区間で使える技」「今回の消費上限」を設定する。「＋ 区間を追加」で増やし、「次の区間」か出力→入力の線で順序・ループを作る |
| 上段「スタミナ・休息」 | 「最大スタミナ」「残量ありの休息（秒）」「枯渇時の休息（秒）」を全区間共通で設定する。休息を終えると満タンに戻る |
| 下段の技ノード | 右側で性能・攻撃範囲・予告・実行時間・技後待ち・再使用待ちなど、その技が公開する値と「消費スタミナ」を編集する。「この技へ進む条件」の最小／最大距離・中心角度・半角を設定する。線をクリックして条件だけを選ぶこともできる |
| 緑の「条件選択」 | 接続する技の有効／無効と、発動条件のカバーを確認する。「技の接続先を変更」か線のつなぎ直しで所属を変える。グループごとの抽選割合を設定する場所とは分ける |
| 下段「＋ 追加」→「コンボ技を作成」 | 技・待機・順次グループ・並列グループ・条件分岐を組む。グループをダブルクリックして内部へ入り、「前に移動」「後ろに移動」で順序を変える |

**発動条件の距離と、実際に届く攻撃範囲は別。** 青は条件、橙は基準の攻撃形状。照準・首の姿勢・配置で変わる技は実験場で確認する。条件選択の「範囲図の戦闘状況」にある残りスタミナ・首数・形態・表示半径は、図だけに使う仮値で戦闘設定を変更しない。未カバーの橙点も、基準姿勢での目安になる。

#### 何の基準で選ばれるか

共通の距離・方向判定を使い、個別ボスが形態・部位・位置・再使用待ち等を満たす実行可能候補を返す。共通側で区間の候補技とスタミナに収まる候補へ絞り、次の設定で選ぶ。首の確保や技の動き・中断は個別ボスが担当する。

| 調整するもの | 選択への影響 |
|---|---|
| 単独／同時／コンボ／大技の「割合」 | 成立する種別同士の相対比率。単独などは種別内の技IDを等確率で選び、同時は成立する組から選ぶ。技ごとの優先度順ではない |
| 「割合を使う条件」 | 基本の割合か、「直前が単独攻撃」など直前の種別に対応する割合を編集する |
| 「連発を避ける」 | 別候補があれば、直前と同じ技IDの組み合わせを外す。同じ技の別条件ノードを増やしても抽選頻度は増えない |
| 消費スタミナ・今回の消費上限 | 開始できた技の合計分だけ消費する。同時攻撃は合計が残量・上限に収まり、部位重複や排他指定のない組だけ選ぶ |
| 「同時攻撃の禁止」 | その区間で、選んだ2技を同時攻撃の組から除く。コンボ内部の並列処理とは別の設定 |

候補が位置や形態の条件でなくなった場合は待って再評価する。残量不足なら休息へ入り、使い切った場合も実行終了後に休息する。上限に入る技がない場合や、成立する種別の割合がすべて0の場合は設定を見直す。待機をコンボへ入れるだけではスタミナは補充されない。

#### 保存して、技から一戦へ確認する

1. 技ノードの「保存して再生」で、その技を一度試す。成立しやすい形態・位置・スタミナを用意する確認用再生なので、一戦のバランス確認とは分ける。
2. 「保存して戦闘を試す」で区間フロー全体を試す。技の終了・技後待ち・次区間・休息まで見る。
3. 保存済みデータから通常ステージを遊び、[録画とAI分析](#6-記録と感想で調整する)で前後を比較する。

一角獣・竜の試遊では、上部の「ボス・形態・技」を選び「実行」で繰り返し試せる。実行中の技と残留弾・分身・隕石を片付け、射程内へ配置して本番の予告・攻撃・硬直・命中処理を開始する。技候補の抽選・CDを省略し、形態や必要な実行資源の不足は画面に表示する。「停止 / 再開」で止めて選び、「実行」で再生する。「通常AIへ戻す」で手動実行を終えて元の形態・自律選択へ戻る。「終了」で試遊を閉じる。現在の形態・技・状態と自機無敵を上部で確認する。単体で開く入口は `res://gyms/boss_flow_trial.tscn`。海蛇とカスタムコンボは単発試遊を使う。

「変更を保存」は編集元だけを保存し、試遊時に実行用データを生成する。保存先は `data/bosses/ai/<boss>_flow.tres`、`<boss>_action_rules.tres` と、参照する技の `.tres`。**ボスの共通デフォルトへの変更であり、ステージ専用の保存ではない。** 既存F4の `enemy_tuning` はボス本体・技を対象に含めない。

「元に戻す」「やり直す」またはCmd/Ctrl＋Z／Shift＋Cmd/Ctrl＋Zを使える。複数選択、コピー・貼り付け・複製、ノード配置、線、整列も編集できる。通常技の複製は性能を共有して条件を分ける。未保存のまま別ボスへ切り替えず、外部変更の警告が出たら相手の編集を確認する。[操作詳細と選択ルール](stage-production-ai.md#ボスの区間フロー攻撃値タイムライン)をAIへの質問に使う。

## 6. 記録と感想で調整する

1. **基準を確認する。** 担当ステージの既存目標を使い、不足する判断基準は本人と相談する。
2. **通常開始を録画する。** F5で起動し、ラン開始前にF9で「REC 待機」にして、通常のステージ選択から遊ぶ。気になるラン時計の時刻と感想を控える。
3. **AIと分析・相談する。** 録画を直接読んでもらい、条件の近い複数プレイを比較する。観測・原因仮説・変更候補を分けて確認する。
4. **合意した範囲だけ変える。** 配置・候補・重み・ステージ内数値のどれを触るか決め、保存する。
5. **起動し直して再録画する。** 同じ開始条件で遊び、期待した変化と残る問題を比べる。

```text
$speed-balance-analysis
担当ステージの今回の録画を直接読み、180〜240秒の育成が遅く感じた原因を分析して。
既存目標を使い、必要な未設定基準だけ相談して。共通値は固定し、まず分析と調整候補まで。
```

録画はクリア・死亡・退出時に閉じ、F9でも停止できる。途中録画や途中時刻からXP0で始める検証ランは、通常開始の成長比較と分ける。F4で録画中に変えた値は、変更時刻と感想をAIへ伝える。

録画ファイル探しは通常AIに任せる。F10による保存先表示は任意。[AIへの詳しい依頼方法・録画条件](stage-production-ai.md#プレイ記録を読む)と[分析スキル](../../.agents/skills/speed-balance-analysis/SKILL.md)を使う。
