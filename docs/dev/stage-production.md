# ステージ制作ガイド

ステージの仕様と、最低限動く敵・ボスの仮実装を受け取り、道中の配置、見た目、細かい挙動、バランスを仕上げるためのガイド。実装をAIに頼むときは[AI向け資料](stage-production-ai.md)、録画によるバランス調整には[分析スキル](../../.agents/skills/speed-balance-analysis/SKILL.md)を使う。試遊から再比較までは[6章](#6-記録と感想で調整する)に沿って進める。

## 1. 仕様を確認して開く

ステージ仕様でコンセプト・登場敵・フェーズ・目標レベル・ボスを確認する。具体例は[ステージ4](../game/stages/stage-4.md)。記載済み・合意済みの目標を先に使い、今回の判断に必要な未決項目だけを一つずつ相談して決める。

[READMEの起動方法](../../README.md#godot-で開発する)に沿ってGodotを開く。ファイルシステムから `data/stages/stage_4.tres` など、担当ステージのリソースを選ぶと「出現タイムライン」が開く。F5からステージを選んで、まず今の状態を遊ぶ。

## 2. タイムラインを触る

上から時間の目盛り、フェーズ（時間帯）、雑魚の数、強敵のクリップが並ぶ。

| 編集するもの | 見方と基本操作 |
|---|---|
| フェーズ | 区間ごとの狙いを置く。境目をドラッグして開始時刻を変え、区間を選ぶと詳細をインスペクターで開ける |
| 雑魚の曲線 | 種類ごとの「その時刻にいてほしい数」。空いた所をダブルクリックで点を追加し、点をドラッグして時刻と数を変える |
| 強敵のクリップ | 群れを出し続ける区間。空きトラックをダブルクリックで追加し、棒の移動で開始時刻、右端で長さを変える |
| ボス・終了ピン | 上段のボタンで再生位置へ置き、ドラッグで時刻を変える。ボス出現と時間帯の区切りをそれぞれ確認する |

雑魚の種類を増やす入口は「雑魚敵」、強敵の行を増やす入口は「強敵」。強敵を配置するときは、ステージの `Enemies` に種類を登録し、クリップの `Types` で使う種類、`Spawn assets` で編成シーン、`Formations` で使う並びを選ぶ。`Group counts` は同時にいる群れの数、`Interval` は次の群れを出すまでの間隔。

**出現数と攻撃の重なりは別々に調整する。** 出現数は曲線・クリップ・編成、同時に発生する攻撃はフェーズの「予算」と敵の種類ごとのvalueで扱う。

<details>
<summary>攻撃の重なりを調整するとき</summary>

valueはステージの `Enemy attack values`、攻撃待ちの優先度はクリップの `Attack Priority` から変える。`Formations` の `Auto` は全員が同時攻撃した場合の個体合計、`Override` をONにした並びは群れ全体で指定valueを共有する。

</details>

同じ編成を繰り返すときはクリップをコピー・貼り付けする。元の右側の同じトラックに置かれる。赤枠が出たらクリップにカーソルを当て、理由と修正方法を読む。操作の追加説明はタイムライン右上の「？」と[設計書の詳細操作](../architecture.md#142-出現タイムラインのエディタ拡張)、攻撃予算の判定は[共通仕様](../spec.md#117-敵の攻撃の形)を参照する。

## 3. フェーズの狙いを配置にする

ボス前に求める装備の完成度を起点に、フェーズごとのレベルアップ回数と「何秒に1回選ばせたいか」を配分する。その累計を各時点の目標レベルにし、ステージ仕様に置く。[ステージ4の成長目標](../game/stages/stage-4.md#2-フェーズと成長目標)を例として参照できる。仮目標も状態を保って比較に使う。不足する基準は分析スキルで相談し、採用する数値は制作者が決める。

- 育成区間では、経験値を得る機会を増やす。倒せる数、落ちる量、拾える量を試遊で見る。
- 同じフェーズ内でも雑魚の曲線を上下させ、敵が押し寄せる山と、駆け抜けたあとの間を作る。
- 強敵は単体を確認してから組み合わせる。数・配置で作る圧力と、攻撃予算で作る重なりを見比べる。

タイムラインの目盛りをクリックして「再生」を押すと、その区間の出現を確認できる。通しで育った装備・レベルとの比較は、先頭から遊んで確かめる。途中再生の初期条件は[記録の分析ルール](../architecture.md#開始条件と分析の読み方)を参照する。

## 4. 敵とボスを設計する

ステージに出す雑魚・強敵・ボスは、モチーフの設定と形から「高速移動でどう戦い、どうなぞると気持ちよいか」を考えて作る。具体例は[ヒュドラの体験と攻撃の整理](../game/bosses/hydra.md#1-狙う体験と攻撃の整理)。

1. **脅威と快感の組にする。** プレイヤーが受ける脅威と、それを高速移動と突進で覆す快感を組で決め、技はこの組から導く。
2. **攻撃を「近距離／遠距離 × 点／線／面」で整理する。** 点は噛みつきや塊のような局所の攻撃、線はビームのように長さを持つ攻撃、面は爆発のようにその地点の範囲を占める攻撃。ステージの雑魚・強敵・ボスの攻撃を同じ表に並べ、分類の偏りと、避け方・攻め方まで同じ技の重複を見直す。山ごとに違う分類の攻撃を組み合わせ、道中の体験を変化させる。
3. **高速で動く自機に対して成立させる。** 逃げ続ければ済む攻撃には、攻撃範囲・向き・残る障害物などで進路を選ぶ理由を持たせる。
4. **大技には、避ける以上の判断を求める。** 回数や範囲の増加より、通る道・進む方向・攻め始める位置を考えさせる。攻撃後に残る配置を、一筆でなぞる経路にする。
5. **体の形で無理なく出せる技にする。** 本体・部位の形と動ける範囲から技を選ぶ。
6. **ボスの技に役割を分ける。** 通常技は部位や形態の個性、組み合わせ技は特性の重なり、大技は戦場全体の動き方の変化を担う。
7. **攻撃と反撃の隙を一続きで作る。** 構える→狙いを固定する→攻撃する→止まる、までを1つの流れにし、止まった配置から攻めどきが分かるようにする。大技のあとは反撃の時間を取る。
8. **技の絵と遊びを決めてから行動判断へ落とす。** 自機の位置、参加できる部位、途中で倒された場合、終了後の配置を詰め、欠けても別の技へ移れる形にする。数値と立ち回りは試遊で決める。

## 5. 敵の動きと見た目を仕上げる

上部の「▶ 実験場」で敵を置き、まず単体で予兆・攻撃・攻めどきを確認する。そのあと本番の編成へ戻して、周囲の敵がいる状態でも成立するかを見る。[実験場の操作](../spec.md#201-敵ルート実験場)を必要なところから参照する。

見る軸は「何が脅威か」「どう対処すると気持ちよいか」。攻撃の向きや範囲が読めるか、狙って避けたり倒したりできるか、見た目と当たり判定が合っているかを確かめる。共通の接触ルールは[戦闘仕様](../spec.md#72-接触)、ボス固有の動きは対象ボスの仕様に合わせる。

数値は「プロジェクト → ツール → データ編集」やインスペクターで調整する。HPの計算と素材の差し替え先は[AI向け資料](stage-production-ai.md#編集先を選ぶ)を参照する。

## 6. 記録と感想で調整する

録画はプレイ中の数値・出来事を保存するJSONL。[分析スキル `speed-balance-analysis`](../../.agents/skills/speed-balance-analysis/SKILL.md)を使って、次の順で調整する。

基礎担当はステージ4等を使い、合意した範囲で共通XP・機体強化幅等も調整する。ステージ制作担当はその基礎値を前提に担当ステージ固有の配置・出現・敵の局所設定を調整する。共通値や共通敵定義に関わる課題は基礎担当へ相談する。

1. **目標と範囲を確認する。** [3章](#3-フェーズの狙いを配置にする)の既存目標を使い、今回必要な未設定基準だけ一つずつ相談する。目標数値は制作者が決める。
2. **録画して試遊する。** 開発版をF5で起動し、ラン開始前のメニューでF9を押して「REC 待機」にする。通常のステージ選択から先頭から遊び、気になったラン時計の時刻と感想を控える。
3. **AIに直接読んで分析してもらう。** 下の例でスキルを呼び、対象ステージ・試遊した日時や範囲・目的・感想を伝える。AIが保存先と対象JSONLを確認するため、通常はフォルダを開いたりファイルを探したりする作業は不要。指定したい録画があれば、そのパスを渡せる。
4. **調整内容を相談する。** 目標との差、条件の近いランの統計的分析、原因の仮説、少数の調整候補を確認し、触る項目・狙う変化・再試遊の確認点を合意する。
5. **合意した範囲を変更する。** 自分で編集するか、その範囲を明示してAIへ実装を依頼する。分析の依頼だけで目標や共通値の変更を許可したことにはしない。
6. **再録画して比較する。** 開始条件・基礎値・比べたいビルド等を揃えて遊び直し、変更前後の録画と感想を同じスキルで比較する。差と不確実性から次の試遊条件を決める。

録画はクリア・死亡・ラン退出時に閉じ、F9でも手動停止できる。プレイ中のF9開始は成長を保った途中録画、タイムライン途中再生はその時刻から初期の成長状態で始める区間検証ランとして扱う。タイムラインは時刻0からの再生も通常開始と区別する。通常成長の調整には通常開始の録画を優先する。形式・保存先・開始条件の詳細は[設計書14.3](../architecture.md#143-プレイの記録)を参照する。

<details>
<summary>保存先を自分で開きたい場合（任意）</summary>

保存先は各端末の書類フォルダ内 `SPEED/recordings/`、書類フォルダを取得できない環境ではGodotの `user://recordings/`。録画・待機が有効な間はF10でも開ける。F9で無効にするとF10も無効になる。ラン終了後は待機が続く。

</details>

### AIへの依頼例

Codexでは次のように頼む。

```text
$speed-balance-analysis
モード：ステージ制作。担当ステージ固有の値だけを対象にする。
対象：担当ステージと、今回の試遊日時・範囲を伝える。録画は保存先を確認して直接読んでほしい。
目的：育成区間の成長速度。感想：「180〜240秒に選択が少なく感じる」。
既存目標を使い、必要な未設定基準だけ一つずつ相談し、統計的な比較と調整候補を示してほしい。
まず分析と相談まで。数値変更は内容を合意してから依頼する。
```

自動検出しない環境やClaude等では、先頭行を「リポジトリの `.agents/skills/speed-balance-analysis/SKILL.md` を読み、必要な参照文書とともにその手順を使ってほしい」に替える。基礎調整ではモードと対象とする共通値の範囲を明示する。アクセスできない場合や候補ランを特定できない場合だけ、AIから必要な保存先・日時等を確認する。AIの実作業は[AI向け資料](stage-production-ai.md#プレイ記録を読む)、統計手法は[スキルの参照文書](../../.agents/skills/speed-balance-analysis/references/measurement.md#複数ランの比較と不確実性)を使う。
