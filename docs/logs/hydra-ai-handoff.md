# ヒュドラの敵AI調整：引き継ぎ資料

ステージ4のボス「ヒュドラ（うみへび座）」の立ち回り・攻撃選択・耐久を、別のAIが既存の意図を保って調整するための資料。会話での判断理由、参照すべき実装、試遊の観測、未確認事項をまとめる。対象は本番Godotのヒュドラであり、ステージ全体や全雑魚のバランス変更は別の依頼として扱う。

本書は**引き継ぎ時点の実装を読むための報告**で、ゲーム仕様や数値の新たな正本にはしない。仕様は [ヒュドラ専用仕様](../game/hydra.md)、現在値は [BossDef](../../speed/data/bosses/hydra.tres)、実際の挙動は現在のコードを優先する。引き継ぎ基準のヒュドラ変更は `04e2e70`。その後のGit差分も必ず確認する。

## 1. 最初に押さえること

1. ユーザーは一通り実装したボスを試遊し、実際の見た目と手触りから調整している。初回実装タスクの完了と、プレイ品質の承認を区別する。
2. 主な狙いは「高速で自由に移動し、一筆で頭をなぞって攻める」こと。敵は高速移動し続けるプレイヤーに対して脅威になる必要がある。
3. 分離後の蛇は、広く散らばりながら羅針盤を持つ不死の蛇を守る。全員が同じ場所に集まると、範囲攻撃でまとめて壊れて体験が成立しない。
4. 通常技は5種類×2技。大技は合体3技＋分離2技。種類依存のコンボ3技は大技とは別枠。
5. 本体と不死の蛇には普段から直接攻撃できる。防衛は首の配置と攻撃で行う。バリアや装甲不足による反射を防衛の代わりに追加しない。
6. 未合意の新ギミック・バランス数値は独断で採用しない。既決事項の確認を繰り返さず、必要な相談は具体的な案を付けて一つずつ行う。
7. 今回の文書化は調整実装の追加許可ではない。受け手は、次のユーザー依頼とその範囲を確認してから変更する。

## 4. なぜこのボスなのか／設計の軸

全5ステージのうちステージ4を最小の制作モデルにし、遊べる状態で絵担当へ渡し、別の友人にもステージ量産を手伝ってもらいたいという背景がある。単にボスを動かすだけでなく、技とAIの調整先が分かり、絵・VFXを差し替えられる構造が必要。

ヒュドラは再生する多頭の蛇、中央の瓦礫、取り込まれた羅針盤、不死の蛇という設定を持つ。神話の再現より、この形状とSPEEDの「線を描いてなぞる攻撃」が噛み合う体験を優先する。

敵の整理は **コンセプト→脅威と快感**。攻撃は **近距離／遠距離 × 点／線／面** で読む。点は局所的な頭・塊、線は長さを持つビーム・風刃、面は一定領域を占める攻撃。

ユーザーの重要な判断基準：

- 「大技はただ回避する以上の不自由を要求する」。回数・範囲だけを増やすと、普通に高速移動するだけで終わる。
- 停止した頭が直線や簡単な一筆の形に並び、「今ここをなぞればよい」と絵で分かることに価値がある。
- 危険を避ける位置と、その後に反撃する経路をつなげる。長い無敵待ちや、理由の読めない反射で行動を止めない。
- 首の種類ごとの役割を保つ。通常技の別名・単純強化版を増やすだけでは足りない。
- AIは技の絵だけでなく、位置、欠員、攻撃中の相手、硬直、予算、発動不能時の行動まで含めて成立させる。ただし、技が決まる前にBTの抽象設計だけを延々と進めない。

## 5. 戦闘の骨格で保持すること

詳細なゲームルールは [専用仕様2〜3章](../game/hydra.md#2-戦闘の進行)を正とする。調整時には特に次を壊さない。

| 局面 | 保持する体験・処理 |
|---|---|
| 合体開始 | 噛みつき・渦・瓦礫の3本。根元は丸い胴体表面に固定 |
| 首増加 | 中央の残HPに応じ3→5→8本。短い無敵と増加演出。閾値超過ダメージを持ち越し、通常首はダウン分を含め全回復 |
| 5本 | ビーム・雷が加わり5種類を1本ずつ持つ。合体大技が候補になる |
| 8本 | 噛みつき2、渦2、瓦礫1、ビーム2、雷1。不死の蛇はこの8体と別 |
| 合体の通常戦闘 | 中央へ直接ダメージを与えられる。周りの首が攻撃と位置取りで中央への接近を防ぐ |
| 首を削る | 合体中は再生待ち。全首ダウンで保証された中央へのチャンスタイム |
| 火 | 首を倒した際の再生待ちを延長し、安全に中央を攻める時間へつなげる |
| 中央破壊 | 勝利ではなく分離開始。不死の蛇が羅針盤を持って逃げ、通常蛇は回復して独立する |
| 分離後 | 通常蛇は撃破後に復活しない。不死の蛇を守るように散開・攻撃し、繰り返すほど通常蛇が減る |
| 本命 | 不死の蛇へ普段から直接攻撃できる。通常蛇の全滅は本命への攻撃条件ではない |
| 最後の1体 | 不死の蛇が短く逃げ、振り返って一度噛み、頭を止める。撃破で勝利と羅針盤解放へつなぐ |
| UI | 上部の大ゲージは合体中の中央→分離後の不死の蛇。通常首HPは頭の近く |

「不死」は設定上の呼称で、ゲーム中に永続無敵という意味ではない。常時無敵や突進1回で強制処刑する対象として扱わない。

通常技後は他の首が攻撃を続ける。大技・コンボ終了後と全首ダウン時は全体で隙を作る。HPゼロ、攻撃後の停止、全体硬直、配置待ちを同じ「ダウン」として一括処理しない。

## 6. 通常10技：識別と調整先

技の詳細は [専用仕様4章](../game/hydra.md#4-通常攻撃)、動作は [hydra_normals.gd](../../speed/scripts/bosses/hydra_normals.gd)。以下の距離は発動条件であり、実際の軌跡・当たりの長さとは別。現在値は `hydra.tres: normal_rules` を読み直す。

| 種類 | 内部ID | プレイヤーに要求する判断／特に保つ差 |
|---|---|---|
| 噛みつき | `bite_thrust` | 位置を捕捉し、頭が直線的に伸びる。かわした後の頭を攻める |
| 噛みつき | `bite_sweep` | 弧を描く横薙ぎ。直線噛みとは避ける経路を変える |
| 渦 | `wind_band` | 一定時間吐く風の帯で通常速度の自機を押し返す。高速移動・なぞりには風を作用させない |
| 渦 | `wind_blades` | 首を振り、三日月の風刃を角度違いで3枚放つ。イルカの単発風刃と区別する |
| 瓦礫 | `rubble_lump` | 狙った方向へ大きい塊を投げる。追尾しない |
| 瓦礫 | `rubble_fan` | 細かい瓦礫を扇状に放つ。頭の側面や弾間へ抜ける |
| ビーム | `beam_fixed` | 1本の持続射線を一定時間残す。狙い固定後の線を読む |
| ビーム | `beam_bolt` | 短い光の棒が飛翔する。発射瞬間に全射線へ命中する狙撃連射とは別 |
| 雷 | `thunder_headbutt` | 引いて帯電→位置固定→頭突き→到達点周囲の瞬間放電→停止。直接頭で殴る案はユーザーが採用 |
| 雷 | `thunder_drop` | 自機の進行先に円を予告し、位置を固定して落雷する |

攻撃開始時の `n.target` に自機位置を捕捉する。落雷は速度×`thunder_lead`を加える。発射後も常に自機を追って頭を振り続ける変更は、ガクつきと回避不能の原因になる。

瓦礫は共通の硬い瓦礫として扱う。HPと装甲・Gateは異なる仕組みなので、硬さを上げるために未知の防御仕様を追加しない。種類別リソースのGateと実行時の上書きを先に確認する。

## 7. 大技5種とコンボ3種

### 7.1 大技

| 内部ID | 局面・開始条件の実装 | 参加者喪失と調整上の要点 |
|---|---|---|
| `north` 同時噛みつき | 合体5本以上。`front_heads()`で自機側の生存3本を選べる | 参加3本のどれかを失えば中断・全体硬直。横一列に停止する頭をなぞれることが目的 |
| `sequence` 順番噛みつき | 合体5本以上。同じく前方3本 | 順番ごとに構え、狙い固定、伸長、停止。3本の連携として読み取れること。欠員で中断 |
| `curve` 曲線ビーム | 合体5本以上、開始時に生存首3本以上 | 全生存首が種類を問わず参加。外向き放射＋本体回転＋先端の遅れ。欠員の射線だけ消え、全滅で中断 |
| `swarm` 連続飛びかかり | 分離後、開始時に通常蛇2体以上 | 全生存通常蛇が独立した出発点へ泳ぎ、時差で直線突進。欠員の番を空ける。隊列追走に変更しない |
| `grid` 格子ビーム | 分離後、`grid_plan()`が成立する | 種類を問わず全生存通常蛇が候補。優先枠を埋め、当初から一筆で射線間を縫える。欠員で穴が広がり、照射後の再配置で塞がない |

現在の `_tech_ok()` は、この表の生存判定と形態条件をコード側で持つ。「行動可能」の全要件をBTの枝だけで表現しているわけではない。コンボはidleの相手を選び、大技は生存参加者を選んで他の通常攻撃を中断する。調整時は仕様上の表現と実装を照合する。

前方3本の技では本体全体を少し回して合わせ、残りは待機する。本体表面を根元が滑る動き、常時ぐるぐる回る本体、背面の首が胴体を貫いて噛む動きは避ける。

### 7.2 格子の正式仕様と仮実装を混ぜない

- ユーザーの案は、中央の小四角＋その四隅から画面四隅へ伸ばす線で中央・上・下・左・右の5領域を作り、自機の領域で配置を選ぶもの。
- 各配置は射手位置、射線の方向・長さ、ポジション優先度を持つ。残存蛇が最低数未満なら使わず、多い場合は優先度順に埋める。
- 射線を1本ずつ壊して開通する迷路ではない。最初から一筆で間を縫って不死の蛇へ届く構造にする。途中の蛇を倒すのは任意。
- **正式5配置は未受領・未確定。** 全5領域が現状は同じ `provisional` を参照する。ユーザーの「一個適当に」は格子の仮配置だけの許可で、大技全体を適当に作る許可ではない。
- `hydra_grid.gd` は領域判定→優先枠抽出→回転・縮小・配置全体の内寄せ→画面内確認→一筆の長さ上限と射線との間隔確認を行う。結果は `path`、`beams`、`bearer` 等。
- `hydra_boss.gd:grid_plan()` はさらに不死の蛇・射手の天体重なりと経路の天体交差を調べる。成立しない場合は候補から外す。
- `path` は成立性を検証するための経路で、通常蛇が隊列で走る移動経路ではない。全蛇をテレポートで並べず、操舵で配置へ到達させる。

### 7.3 コンボ

| 内部ID | 必要な種類 | 成立させる絵と仕組み |
|---|---|---|
| `tornado` | 渦＋瓦礫 | 渦首の前へ瓦礫首が石を投入し、巻き込んだ竜巻を渦首が発射。渦が拾った物を遠くの瓦礫首が無理由に操作する構図にしない |
| `debris_shatter` | 瓦礫＋ビーム | 瓦礫を展開し、ビームで砕いた箇所から破片を飛ばす |
| `beam_pincer` | ビーム＋別個体のビーム | 2体がそれぞれ1本を担当し左右から挟む。1つの頭から二又ビームを生やさない |

コンボは両形態で使う。発動機会は全体共通で、成立するコンボから重み付き抽選する。相手不足なら機会を保持し、実行を選んでから参加者を確保。どちらかを失えば中断して全体の隙を作る。コンボ実行中は他の通常技を待たせる。

竜巻は既存の岩素材、投入の弧、巻き込まれる石、風の筋と暗い雲のピクセルシェーダーで改修済み。ただし「改修済み」をユーザーの品質承認と読み替えない。形・判定・寿命・世界時間を一致させる。

## 8. 現在のAI構造と実際の編集先

### 8.1 責務の分担

```text
RunManagerの戦闘更新（real_dt / world_dt）
  → BossManager.tick
    → HydraBoss.sim_tick
      ├─ 成長・分離移行・制限時間の一撃などの専用状態
      ├─ 合体本体移動 / 不死の蛇の移動
      ├─ 全体硬直・全首ダウン・再生
      ├─ 分離後に画面へ向かう通常攻撃候補を選択
      ├─ 各首：通常技を進める / idle時に首別BTを実行
      ├─ 本体BT：コンボ優先、次に大技
      ├─ 大技配置→Timeline→連続動作
      └─ 頭位置・胴の追従・攻撃形状の判定・演出イベント
```

本体は `LimboHSM/Form1` の `BTState` を使い、合体・分離の条件は役者状態で判定する。エディタに形態数ぶんのHSM状態が並んでいるとは限らない。首BTは頭の生成時にcloneしてBlackboardへ `head_index` を入れる。

本体Blackboardへ現在渡す主な値は `player_distance`・`player_angle`・種類別 `live_heads`・`neck_count`・`recovering`。互換用の `exposed` はfalse。これらだけで全状態を表現しておらず、独自BTタスクは役者の関数も呼ぶ。「Blackboardへ値がある」と「現在の枝がその値を使っている」を分けて読む。

戦闘状態は `Neck` の `mode`・`t`・`cd`・`locked`・`target`・`strike_pos`・`row/row_id`等とEnemyTableにある。`Neck.head_hp`は被弾差分を見るための直前HPでもあり、`def.params.head_hp`の設定値とは用途が違う。描画ノードのpositionだけを直接動かして修正を済ませない。

通常技・配置・再生・操舵・VFXはスローや停止を含む世界時間で揃える。新しいTimerや描画フレームのdeltaだけで技を進め、止まったゲーム中に攻撃だけ進む状態を作らない。

### 8.2 通常技の選択

首別BTは「重み付き通常技抽選→候補が全て失敗したら `position_head()`」の構造。各技は `normal_ready()`→`start_normal()`。重み付きselectorはランのRNGを使用し、失敗した枝を外して次の候補を試す。

`normal_ready()` の主な条件：

- 生存し、種類が一致し、idleで個別CDが終わっている。
- 大技中・全体硬直・全首ダウンの隙・成長中・分離待ちを除く。
- **頭が画面内に入っている。** 頭半径ぶんの余裕を持つview rectで判定する。
- 頭から自機までの距離が `normal_rules[技].min/max` に入る。
- 合体中は取り付け方向から大きく外れた自機に向けて開始しない。
- 実行中の各通常技の `cost × attack_value` と次の技の合計が `normal_budget` 内。

このため「BTの重みを上げれば必ず攻撃が増える」とは限らない。画面内・距離・予算・全体状態・CDで候補が落ちている可能性を先に切り分ける。画面内へ入れる移動先と、種類ごとの実際の射程も揃える。

`start_normal()`は通常ランの雑魚予算と分離している。`AttackDirector.formation_mode` がtrueの通常ランでは外部の雑魚枠取得を省略し、ヒュドラ専用の `normal_budget` を使う。実験場でformation_modeがfalseのときはディレクターの制約にも従う。

### 8.3 コンボ・大技の選択と時間

本体BTはコンボselectorを先に、次に大技selectorを調べる。`attack_ready()`は読み取りのみで、選択後の `try_start_tech()` が実行枠を要求し、参加者確保、通常技中断、Timeline開始を行う。条件の評価だけで予算・CDを消費しない。

- 共通コンボ待ち：`combo_wait`／`combo_cooldown`。
- 大技の共通待ち：`_tech_cd`／`tech_cd`。
- 技ごとの待ち：`_tech_until`。`<技ID>_cooldown` があれば使い、なければ共通値を使う。BTActionの `cooldown_scale` も掛かる。
- 技終了時・中断時：`tech_end()`で全体硬直 `tech_recovery` を開始し、残った攻撃・瓦礫・参加状態を片付ける。
- 分離大技：配置待ち中はTimelineを止め、`special.position()`で到達と画面内を確認してから再開。`formation_timeout` で永久待ちを防ぐ。

技ごとのCDを「その秒数ぴったりで必ず発射する周期」と解釈しない。共通待ち、選択、配置移動、予告、他技の実行も間隔へ加わる。

### 8.4 位置取りと分離後の最新変更

`04e2e70` では、同距離を回る護衛配置と「画面外に出た全蛇を同じ画面へ戻す処理」を変更した。現状は以下の仮の立ち回り。

- `_guard_patrol()`：不死の蛇を中心に、自機の接近側へ少し寄せた広い領域を作り、壁内側と交差させる。各蛇に異なる基準方向、内外の距離、巡回周期を与える。
- `_update_guard_approach()`：実行中の通常技予算を差し引き、CDが終わったidle蛇を待ち順、同順なら自機への近さで並べ、予算に入る候補を選ぶ。
- `position_head()`：選ばれた蛇だけ画面内の分担位置へ向かい、その他は巡回する。近すぎる生存蛇から離れる補正を目標へ加える。
- `steer_snake()`：通常は胴の長さを考慮して壁内側へ目標を置き、天体表面を回り込む。画面端で必要な場合と陣形配置は、頭を入れる余裕の扱いを切り替える。

これは厳密な「攻撃予約」ではない。画面へ向かう候補と実際の技抽選は別で、画面内の別蛇も条件を満たせば開始できる。実際の同時攻撃数は `normal_ready()` の予算判定が制限する。

`guard_radius`の現在の実装は、単一の護衛円半径をそのまま回るものではなく、`_guard_patrol()`で領域の基準値として倍率を掛けて使っている。単純に数値だけを小さくして全員を寄せると、まとめ撃破の問題を再発させる。護衛の広がりや待ち順の係数にはコード上の定数もある。

**ユーザーによる最新変更後の再試遊は未確認。** 角での短い再現確認が通ったことと、移動する自機・全解像度・全ビルドで面白く守れることは別。

### 8.5 蛇らしいモーション

ユーザーは「直線的に自機へ追跡」「移動して急停止し、その場で回転」「機械的な向き変更」を明確に拒否している。上下左右の旋回、直進、曲線移動、被弾、構え、攻撃、停止をつなぎ、体をうねらせて回り込むことが必要。

`hydra_snake_motion.gd`は最大旋回速度と加減速で頭を動かし、頭が通った軌跡を胴がたどる。`motion.weights`のswim・turn・hit・windup・attack・holdを世界時間で混ぜる。専用の完成スプライトアニメーションが全方向分納品済みという意味ではなく、現状は手続き的な姿勢と合成の実装。

合体首の骨計算と分離蛇の軌跡追従を混同しない。描画だけを動かして当たりを置き去りにせず、頭の戦闘座標と表示を一致させる。

## 13. 性能を壊さない

ヒュドラ戦の重さは強い不満として出ている。`5b1a91c`では固定壁をアトラス付きArrayMeshへ、仮首描画をキャッシュしたArrayMeshへまとめ、`safe_point()`を円と矩形の候補計算へ変更した。

同じ600敵を置いた短いGUI比較では描画呼び出し約628→100/フレーム、600フレーム所要約10.97→4.26秒。安全点計算の単独比較も短縮している。これは固定条件の比較で、本番全てのフレーム時間が保証されたという意味ではない。

調整時の注意：

- 首の節ごと・壁の岩ごとに大量の個別描画呼び出しを戻さない。
- 表示用の姿勢更新を同じ固定更新で何度も呼ばない。最終の頭位置から一度だけ胴を追従させる。
- `safe_point()`を候補ごとに全地形へ何十回も試すような探索へ戻さない。
- 8体の近接回避と、全雑魚数に比例する重い探索を区別する。新しい毎フレーム全敵探索は測定して判断する。
- 装飾シェーダー・粒子の追加は描画コストと見やすさを確認する。品質を下げるためだけに危険範囲の表示を削らない。

## 14. 調整確認の入口

### 14.1 通常ランと専用試遊を分ける

本番はステージ4の通常ボスにヒュドラが接続されている。出現時刻は現在のstageリソースを読む。過去記録の495秒をハードコードしない。
