# 機体強化画面の仮UI（2026-10-09）

ShueMaker70969 が指定した「中央の機体ワイヤーフレーム、各強化部分への引き出し線、部位名のボタン、ホバーで右に効果と金額」という構成の見本。外観と操作の候補、未採用・未実装。

![機体強化画面の案](../art/ship-upgrade-wireframe-v1.png)

## 配置

- 中央の機体図から部位ボタンへ引き出し線を伸ばす。右に固定の詳細パネル、上に画面名と所持部品、左下に戻るボタンを置く。
- 既存の強化項目「衝角素材」「機体フレーム」「回収装置」「主推進器」「充電効率」「学習回路」「演算予備」を配置。部位との関連付けはUI上の仮案で、強化効果の追加・変更ではない。
- ホバー中は部位・線・名前をシアンで連動して強調する。右には名称、現在Lvと次Lv、効果、必要部品、購入後の残り部品を示す。

## 操作の提案

- ホバーは情報の表示のみとし、右の「強化する」で購入する。
- 部位から右の購入ボタンへ移動できるよう、カーソルが外れても最後に示した詳細を保持する。他の部位にホバーしたときに切り替える。
- キーボードのフォーカスとタッチの部位タップも同じ選択表示にする。部品不足時は購入を無効にし、不足が分かる文言を出す。最大強化では次Lvと購入ボタンを最大強化の表示へ置き換える。
- 初期選択やクリックによる固定の有無は実装前に判断する。

## 見本の扱い

組み込みimagegenで制作し、既存自機PNGを輪郭の参考に使った。純粋なワイヤーフレームより外装の白い面が多い生成結果で、完成アートではない。主推進器の最初の強化効果と費用は既存データを参照、所持部品は仮例。段階の小四角は見本で全項目同数になっているが、実装では各 `.tres` の強化上限に合わせる（演算予備の上限は他の項目と異なる）。画像の機体寸法・画面比率はゲームの原寸や固定解像度を指定しない。

既存 `speed/scripts/ui/upgrade_screen.gd` は一覧型のまま。購入処理は既存の `SaveManager.buy_upgrade()` と `.tres` を利用する想定。生成指示は [prompt](../art/ship-upgrade-wireframe-v1.prompt.txt) に保存。
