# 計測の読み方

記録形式の定義は[設計書14.3](../../../../docs/dev/architecture.md#143-プレイの記録)を参照する。以下は調整判断のための読み方。各項目の存在と意味を入力録画・記録処理で照合する。

## 照合する実装

リポジトリルートから辿る。

- `speed/scripts/managers/play_recorder.gd`：JSONLへの出力・区間集計・F9・性能窓。
- `speed/scripts/runtime/run_simulation.gd`：`recording_origin`・`recording_snapshot()`、ラン/世界時計とボーナス。
- `speed/scripts/managers/run_manager.gd`、`speed/addons/stage_launcher/`、`speed/addons/spawn_timeline/`：開始経路。
- `speed/scripts/runtime/systems/loadout_system.gd`：必要XP、装備の取得・交換・おまけ強化。
- 同じ systems 内の `pickup_system.gd`・`spawn_system.gd`・`combat_system.gd`・`ship_system.gd`・`enemy_system.gd`・`boss_system.gd`：XP供給、出現、命中/撃破/被弾の発生元。

改修で移動していればシンボルと呼び出し元を `rg` で追う。ゲーム内イベントの存在と、recorder がその内容を保存することを区別する。

## ステージ固有の変更先を確かめる

現行の `StageDef.enemy_attack_values/priorities`、時間帯の `attack_budget`、クリップの `formation_values/attack_priority` は攻撃の同時実行枠・優先度を制御する。攻撃ダメージや射程の上書きとして使わない。クリップの `interval` は群れの出現間隔で、敵の `params.fire_interval` とは別の値。

通常ランの敵種は共通 `EnemyDef` を参照し、HP・攻撃・射程・間隔等の適用元を敵ごとの実装まで辿る。実験場用の定義差し替え経路があっても、通常ステージの編集機能として使えるとは限らない。改修仕様に RuntimeStage や Enemy Resource の構成が記載されていても、対象項目・適用経路・実装状況を確認するまでステージ別上書きが使えると判断しない。必要な局所設定がない場合は基礎側へ相談し、共通敵種を直接編集して代用しない。

## 目的別に使える指標と限界

| 調整目的 | 観測・集計できること | 推定に留まること・確認すべき不足 |
|---|---|---|
| ステージの密度・忙しさ | `sample.enemies/in_view/by_star` の時点値、種類別の区間撃破数、クリップ群の出現と終了、被ダメージ、攻撃予算の最大使用量 | 全雑魚の出現数・出現位置・滞在時間、画面上の弾密度の履歴、攻撃開始/終了・予算待ちの理由は復元できない。予算最大値だけで重なった攻撃の組合せを決めない |
| 敵攻撃力・危険な攻撃 | `sample.damage` の攻撃原因/発生元別のダメージ量、HP/最大HPの推移、死亡時の `last_hurt` | 被弾1回の量・回数・正確な時刻、攻撃試行数・回避率・防御で無効になった回数を保存しない。量の増加を単発威力の増加と決めない。発生元が空の原因を特定の敵へ割り振らない |
| 成長の速さ・選択機会 | `levelup` の到達秒、`pick` の選択履歴、XPの区間供給/取得、フィールド残存、`xp_config` にある必要XP式 | 通常プレイとして適格な開始条件が必要。選択の遅れとXP獲得の遅れを分ける。回収経路・位置・拾い損ねの原因、英雄の力の時系列は分からない |
| XP出所・大結晶の寄与 | 現行の `big_crystal` は落ちた時刻・敵の種類・段・供給XP。`end.big_crystals` は録画内の段別供給集計 | 大結晶の個体ID、拾った時刻/方法、残存/消失、通常結晶の敵別供給・取得は保存しない。大結晶が落ちたXPを取得XPとみなさない |
| 強敵の硬さ・処理速度 | `strong` の出現秒・生存ラン秒、体当たり回数、原因別ダメージ、とどめ原因、終了時の記録上の状態 | 実効HP・サイズ/エリート補正・個体IDを行に残さず、全個体の対応づけやHP逆算はできない。途中録画より前に出た強敵は追跡されない。`alive` や終了なしは撃破時間として平均しない |
| 武器・特性の寄与 | `sample.dealt/kills_by`、`strong.by_cause/killed_by` による原因別の出力量・とどめ数、記録された選択と最終装備 | ダメージは超過分を含み、とどめ数は削った寄与と異なる。発射数・命中数・敵ごとの実効ダメージ・装備の全変更履歴がなく、正確な武器DPS・命中率・単独の効果は出せない |
| 性能・重くなる時間帯 | `performance` の描画フレーム間隔、閾値超過数、観測時間、ボーナス/描線/突進/ヒットストップの対応、書込時点のオブジェクト数 | CPU/GPUの原因、ハードウェア・解像度・描画設定の一致、窓内の最大オブジェクト数、入力遅延、フレーム時間の分位点は分からない |
| 再現性・前後比較 | ステージ本体ハッシュ、Godot版、保存されたXP設定、開始スナップショット、存在すれば機体強化段と開発上書き | ゲーム版・依存データ全体の版、乱数seed/状態、操作入力、全設定、途中の設定変更は保存しない。ステージハッシュ一致だけでは同一条件にならない |

## 数を読むときの注意

### 成長とXP

`sample.xp_picked`・`xp_dropped` は区間量、`xp_field` は時点の地面の結晶XP。`recording_start.xp_gained/xp_dropped` は録画開始前を含む累計なので、途中録画の区間合計と分ける。観測後の累計取得は開始累計＋以降の区間取得で表せるが、欠けた前半の内訳は復元できない。

大結晶供給量は `big_crystal.xp` の合計で求める。`end.big_crystals` は同じ供給の照合用であり、重ねて足さない。現行の供給経路を照合できれば、`sample.xp_dropped` から同じ区間の大結晶供給を引いた量を「それ以外の供給」と計算できる。結晶の再配置・運搬なども実装で確認し、敵別の取得量へ拡張しない。取得/供給比は、開始時残存とボーナス・時刻の範囲を揃えたときだけ示す。単純な差を消失量と断定しない。

旧形式にある `xp_capsule_spawn/collect/lost`、`capsule_config`、`sample/end.xp_capsules` は、その録画時の仕組みとして別に分析する。現行の `big_crystal` と同一イベントへ変換しない。形式番号だけで互換と決めず、必要なら対応するコード版を利用者に確認する。

### ビルドと原因別の戦闘量

現行の初期武器選択は `upgrade` を出さず、recorder の `pick` に残らない。`pick.bonus` はおまけ強化の回数だけを保存し、対象ID/段を捨てる。空き枠への彗星武器取得も `pick` がなく、交換は `chosen` の文字列から新しい武器IDが欠ける。調整パネルや英雄の力の変更も完全な時系列を保存しない。開始装備が空でも「装備なしで戦った」と解釈しない。

`chosen` の段・最終装備・原因別ダメージから過去の装備を補完した場合は推定とする。原因IDは武器IDとは限らず、体当たり・特性・連鎖・英雄由来等を含む。該当版の武器/特性実装から対応を確認し、曖昧なら原因別のまま報告する。最終装備の全武器をラン全体で装備していたと仮定しない。

`dealt` と `strong.weapon_damage/by_cause` は重複する集計なので足し合わせない。後者の「武器」には recorder が `ram/bump/touch` 以外として数えた原因が入る。`rams` は体当たり命中の回数で、体当たりダメージ量ではない。`finale` 原因の撃破は recorder が除く。ボスの最終撃破は専用イベントで処理されるため、`strong` や種類別撃破を完全なボス台帳として扱わない。

強敵は recorder 内で個体を追うが、`strong` 行にはそのIDを出さない。ボーナスの出入りなどで撃破せず除去された敵を recorder が追跡し続ける場合もあるため、`result=alive` を終了時の実在保証にしない。`clip_group_end` も実装上は群の有効な敵がいなくなった通知なので、全員を攻撃で撃破したと断定しない。

### 時間と性能

ボーナス中の `strong.life` はラン時計の差であり実際に画面上で経過した秒数とは異なる。終端未観測は打ち切りとして分ける。初期出現を欠く個体や未出力の生存個体を0秒に置き換えない。

複数性能窓の総FPSは `sum(frames) / sum(duration_real)`、平均フレーム時間は `1000 * sum(duration_real) / sum(frames)`。閾値超過率とヒットストップ観測率は各回数の合計を総フレーム数で割る。FPSの単純平均や窓ごとの割合の単純平均を使わない。`frame_ms_max` は窓の最大で、分位点へ変換できない。

`real_t` は書込時刻、性能窓は `window_start_real/window_end_real`、`duration_real` は観測した間隔の合計を使う。ポーズ等で窓が分かれる。`objects_at_write` と `bonus_at_write` は書込時点であり、窓の最大/平均や全区間の状態を保証しない。ヒットストップ観測率は停止時間率ではない。処理負荷との同時発生を示しても、ヒットストップそのものが描画FPS低下の原因だとは決めない。

## 不足の優先順位を選ぶ

今回の問いが止まる項目を先に提案する。通常成長の選別には開始条件、前後比較には実行版・依存設定の識別、ビルド別調整には初期選択と全装備変更の記録が特に効く。単発攻撃力と被弾頻度を分離する問いには被弾回数/単発量や攻撃試行、XP出所別の回収を問う場合には大結晶の取得対応が必要になる。

詳細な位置・全攻撃・全フレームの記録を一律に必須としない。既存の集計・感想・短い画面確認で足りる問いかを先に判断し、追加データのコストと判断への効果を示す。追加計測や記録実装は利用者の決定を受けて行う。
