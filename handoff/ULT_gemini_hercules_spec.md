# ULT 詳細引き継ぎ — ふたご座・ヘルクレス座

この文書は、ふたご座とヘルクレス座の**試作に向けた設計・演出の引き継ぎ**。実装の正本は [仕様書 8.1](../docs/spec.md#81-英雄の星座の力) と [各英雄のデータ](../speed/data/heroes/) にある。**本ファイルの内容は未実装の変更案を含む。** 合意済みの方向・試作する暫定案・未決事項を区別し、試作した結果を仕様書とデータに反映する。

関連：[ULT_handoff.md](ULT_handoff.md)（共通方針・ペルセウス座・撮影環境など）。

## 1. 共通方針

- ULTは通常の武器・特性より明確に強く、派手にする。威力を上げるだけでなく、ULTごとに固有の戦闘体験を作る。
- 武器・特性、ほかのULTと性能や演出を重複させない。とくにミラージュ（ブースト経路の時間差追撃）、エスコートウィング（左右編隊）、双極ビーム（2点を結ぶ攻撃）、ペルセウス座（石化・停止）を意識する。
- プレイヤー操作から結果を理解できることを重視する。敵の密集地点を探して自動で分身の軌道を決める方式は採用しない。
- 見下ろし視点。円・点線などの幾何学模様だけで済ませず、材質・輪郭・粒子・動きの質を作り込む。
- pixelFXは技法の参考。固有のエフェクトをGodotで作る。既存の共通爆発やプラズマ、星座や彗星の金の光をそのまま重ねない。
- サイズ、速度、色、光量、細かい時間は決め打ちせず、実際のゲーム画面を撮ったGIFと試遊で調整する。試作と本番で色・形を一致させる。HDRの注意点は共通引き継ぎを参照する。

## 2. ふたご座 — 光と影の兄弟

### 2.1 コンセプト（合意済み）

カストルとポルックスを「光と影の兄弟」として表現する。通常の機体がULT発動時に**光の機体と影の機体に分裂**し、以降は2機で行動する。突進のときは、プレイヤーが描く**1本の線**から生成した左右対称の経路を、それぞれが**同時に**駆け抜ける。

武器の分身追加や自動追撃ではなく、**左右対称に動くことそのもの**をULTの特徴とする。

### 2.2 操作と軌道（試作方針として合意済み）

1. ULTの有効中も、プレイヤーが描く線は通常どおり**1本だけ**。
2. 光の本体はプレイヤーが描いた軌道を走る。
3. 影の分身は、その軌道を左右反転した経路を同時に走る。
4. 対称軸はひとまず**突進開始時の機体位置を通り、機体の向きに平行な直線**を使う。これは暫定案であり、操作感の試作で見直す可能性がある。
5. 分身の進路は描画中に理解できる形で表示する。表示方法・濃度は試作で決める。
6. 敵の分布を調べて自動的に別の攻撃経路を作ることはしない。

軌道が開けば別々の敵を広く攻撃し、重なれば同じ敵へ集中できる。線の描き方でこの2つを使い分けられるようにする。

### 2.3 攻撃性能（試作する暫定案）

- 2機それぞれに独立した体当たり攻撃判定を持たせる。
- ULTの突進中は装甲に弾かれず貫通し、通常の体当たりより強力な攻撃とする方向。
- 同じ敵に両機が命中した場合は、それぞれのダメージが入る方向。
- 装甲以外の特殊な倒し方・ボス・大物に対する扱い、同一敵への再命中間隔、ダメージ倍率は**未決**。
- ULT有効中の通常移動で、影の分身が独立した攻撃・被弾判定を持つかは**未決**。
- 原則として、光と影に別々の状態異常を割り当てず、対称突進そのものの強さを優先する。

### 2.4 発動時の分裂（合意済みの演出）

**分裂はブースト時ではなく、ULTの発動ボタンを押したタイミングで行う。**

参照したユーザー提示画像は、スライム状に伸びた物質が細くちぎれ、穴のある不規則な輪郭へ変わる例。**スライムの緑色や質感を使うのではなく、「粘る→引き伸ばされる→裂ける」の形状と運動を使う**。

演出の構成案：

1. 通常の機体に光と影の差が現れ、輪郭が二重になり始める。
2. 2つの機体が離れ、間の輪郭・材質が高粘度の液体のように伸びる。
3. 伸びた膜の中に不規則な穴が開き、複数の細い糸状のつながりだけが残る。
4. 糸が順にちぎれて完全に分裂し、2機の輪郭が反動で揺れて落ち着く。

引き伸ばされる方向は**2機が離れる方向**。見下ろし視点で下向きに垂れる必要はない。1コマで分離を完成させず、粘性・抵抗・緩急のある動きにする。

参考キーワード：Slime slash effect / Gooey liquid dissolve / Stylized slime VFX / Organic slash VFX / Gooey mesh tear / Slime stretching shader / Viscous liquid splitting / Meat slash VFX。

### 2.5 光と影の材質・輪郭（方向性は合意、具体値は試作）

**機体の基本形状は維持する。主に材質、輪郭の形状、周囲のオーラ、軌跡を変える。**

| | 光の機体（本体） | 影の機体（分身） |
|---|---|---|
| 材質 | 白〜青白い発光の方向 | 黒〜深紫の暗い物質の方向 |
| 輪郭 | 比較的明瞭、光のオーラが流れる | 不規則にうねる輪郭、暗いオーラ |
| 突進の軌跡 | 鮮明な残光と細かい光粒 | 形が崩れながら薄れる暗い残像 |
| 印象 | 鋭さ・明るさ | 重さ・異質さ |

これは色・質感の試作方向であり、色コード、発光強度、輪郭の変形量、オーラの大きさは未決。影が背景と同化しない視認性が必要。

### 2.6 分裂後の通常移動（合意済み）

- ULTが発動したら、**次のブーストを待つ間も2機が同時に存在**する。
- 光と影の2機が寄り添うように**一緒に動き、並走**する。
- 影は本体に滑らかに追従する。固定された硬い編隊ではなく、わずかに有機的な動き・オーラの差を持たせる。
- 具体的な配置、距離、追従の遅れは試作で決める。

### 2.7 突進と再融合（合意済み）

1. プレイヤーが通常の1本の線を描く。
2. 光と影の機体が左右対称の軌道へ分かれ、同時に突進する。
3. 光は鮮明な残光、影は崩れるような暗い残像を引く。重なりや交差で明暗の干渉を見せる場合も、攻撃判定を増やす領域エフェクトにはしない。
4. **突進終了時、影の機体が溶けるように崩れ、同時に光の本体へ合流する。**
5. 影の輪郭が崩れ、糸や不規則な断片になり、それらが光の機体に引き寄せられて吸収される。単なる透明化・瞬間消失にはしない。
6. ULTがまだ有効なら影を本体から**短く滑らかに再形成**し、再び2機で並走する。次のブーストでも同じサイクル。
7. 最初のULT発動時のみ大きな粘性分裂を見せ、その後の再形成はテンポを損ねない短い演出にする。

**分裂時は光と影の両方が引き裂かれる。再融合時は影だけが崩れて光へ戻る**という非対称性をつける。

突進終了位置が離れているときの合流経路、操作の妨げにならない再形成時間、ULT終了時の処理は試作で調整する。

### 2.8 持続時間とクールダウン

現行データ（speed/data/heroes/gemini.tres）は**持続10秒、クールダウン45秒**。

10秒は短いかもしれないという意見があり、**15〜20秒は検証候補**。現時点で15秒や20秒と確定したわけではない。1回のULT中に何回ブーストできるかを実機で確認し、持続時間とクールダウンを合わせて調整する。

### 2.9 採用しない方向

- プレイヤーに2本目の線を任意の位置から描かせる既存仕様。
- 敵集団や密集地点を探索して、分身の経路を自動生成する方式。
- 本体の後を分身が時間差でなぞる方式（ミラージュと近い）。
- 2機に挟まれた領域全体を攻撃する方式（双極ビームと近い）。
- 光と影に単純に別々の状態異常を割り当てることを能力の中心にする方式。

### 2.10 試作で確認する未決事項

- 対称軸が機体の向き基準で直感的か。反転線の予告表示と突進開始・終了時の位置関係。
- 敵の装甲以外の特殊防御、同じ敵への2機の命中、ボス・大物への威力。
- 通常移動中の影の判定と、並走の位置・揺らぎ・追従。
- 粘性分裂のアニメーション、輪郭のオーラ、影の溶解と再吸収のタイミング。
- 途中でULT効果時間が切れた際の突進・影の扱い。
- 持続時間・クールダウン、具体的な攻撃倍率。

## 3. ヘルクレス座 — 火の隕石群

### 3.1 コンセプト（合意済み）

**多数の燃える隕石が次々と直線的に降り注ぎ、戦場のあちこちで岩の衝突・破砕・煙・残留炎が重なる。**

巨大な隕石を少数落とす方向ではなく、**多数の隕石による連続した衝突**を採用する。

### 3.2 現行性能（試作の基準値）

現行データ（speed/data/heroes/hercules.tres）：

| 項目 | 現行値 |
|---|---|
| ULT持続 | 10秒 |
| クールダウン | 50秒 |
| 落下間隔 interval | 0.35秒（10秒で約29発） |
| 落下予告 fall_time | 0.6秒 |
| 着弾半径 radius | 110px |
| 着弾威力 power | 攻撃力A × 3 |
| 地表炎の持続 burn_time | 3秒 |
| 地表炎の威力 burn_power | 攻撃力A × 3 × 0.3 = A × 0.9 / 0.25秒 |

- 落下地点は機体周囲で決め、現在は敵の位置を優先して選ぶ。敵の密集地点を高度に探索する新しい方式は決定していない。
- 着弾時に範囲攻撃し、着弾位置に残留炎を発生させる。火属性はうみへび座の首の再生待ち時間にも関係する（[うみへび座仕様](../docs/game/bosses/hydra.md)）。
- 現行の表示は単純な円による仮実装（speed/scripts/render/equipment/heroes.gd の draw_fire）。
- 現行の数値は今回改めて確定したものではない。まず現行の発数・火力を基準に試作し、試遊で調整する。

### 3.3 隕石本体

- 黒く焦げた不規則な岩を基本とし、赤熱した亀裂や表面を見せる。
- 形状バリエーションを用意し、同じ岩がコピーされている印象を減らす。
- 岩のサイズ、亀裂の量、赤熱の範囲はGIFで見て調整する。今は数値を固定しない。

### 3.4 落下

- **まっすぐ落ちる。** 曲がる軌道や方向転換は不要。
- 真上視点で落下の進行が読めるように、画面上では基本的に**同じ方向から斜めに接近**する表現を試す。
- 岩の後ろに**炎の尾・煙・飛び離れる火の粉**を引く。
- 尾の長さ、速さ、細かい揺らぎ、着弾までの見え方は試作で調整する。角度をランダムに散らして複雑化させることは目的ではない。

### 3.5 衝突・破砕（重要）

**岩石の衝突そのものを主役にする。炎が上へ噴き上がる演出は不要。**

1. 隕石が地面へ衝突し、短い閃光が出る。
2. 岩が不規則に割れ、大小さまざまな破片が周囲へ飛散する。
3. 火の粉が散る。
4. 破片が減速して消え、煙が薄れていく。

**除外する演出：**

- 柱状に噴き上がる炎、大きな火炎の噴出。
- 大きく膨張する火球、衝突と関係の薄い大規模な火炎爆発。
- 共通BlastBurstsに似た汎用爆発や、単純な円形の衝撃波。

破片の個数・形・速度・寿命、閃光の強さは試作で決める。

### 3.6 残留炎・地表

- 衝突位置に不規則な焼け跡・亀裂を残し、内部が赤熱する。
- **炎は地表付近で小さく揺れる。** 炎の柱や大きな噴出にはしない。
- 煙が薄れ、赤熱した地表が徐々に冷え、暗くなって消える。
- 残留炎は継続ダメージの範囲を示す。ただし敵や機体の視認性を妨げない。
- 具体的な地面の形状、煙の密度、炎の高さ、消え方は試作で調整する。

### 3.7 連続落下の画面全体

- 複数の隕石が独立して進行し、「落下中」「衝突中」「破片・煙」「残留炎」が同時に存在する。
- 形状・尾・細かい動きに変化を持たせ、29発が機械的なコピペに見えないようにする。
- ただし基本の落下方向はそろえる。
- 落下間隔のランダム化や終盤の密度上昇は**提案段階であり、まだ合意済みではない**。まず現行間隔で画面を確認する。

### 3.8 色の方向

- 岩：黒〜暗灰色、亀裂：暗赤〜橙。
- 炎：黄白〜橙〜赤、煙：暗灰、冷えた地面：暗赤から黒。
- 星座やレア彗星と重なる**強い金色の光の尾**は避ける。
- 正式な色・明るさはHDRの本番画面で確認する。

### 3.9 性能上の検討事項

- 着弾時の範囲ダメージと残留炎による継続ダメージという構造は維持する。
- 残留炎が複数重なると同じ敵に継続ダメージが重なる現行挙動がある。重複の可否・上限・ダメージ調整は**未決**。「重複させない」と決定したわけではない。
- ボスと大物への威力、落下頻度、対象の選び方は試遊で調整する。
- うみへび座の首の火による再生遅延は維持する。

### 3.10 試作で確認する未決事項

- 隕石本体のサイズ・形・赤熱の割合、落下速度、尾の長さ。
- 着弾時の閃光、石の破片、火の粉、煙、残留地面の品質と見やすさ。
- 同時に多数が落ちた際の画面密度。
- 落下間隔・発数・狙い方、終盤に変化を付けるか。
- ダメージと残留炎の重複処理、持続とクールダウン。

## 4. 制作・検証の進め方

### ふたご座

1. 光／影の機体材質と輪郭・オーラを試作する。
2. 発動時の粘性分裂を短いGIFで評価する。
3. 通常移動中の2機の並走と、1本の線からの左右反転軌道を確認する。
4. 突進後に影が溶けて吸収され、ULT中は再形成される一連の動きを確認する。
5. 実際に操作して、判定・威力・持続時間を調整する。

### ヘルクレス座

1. 赤熱した岩・炎と煙の尾・直線落下を1発で試作する。
2. 衝突時の破砕と火の粉・煙、残留地表の炎を試作する。
3. 1発のGIFを見てから、現行頻度の多発落下を確認する。
4. 視認性・負荷・性能・火の重複処理を調整する。

### 共通

- 仕様相談と実装を分ける。ここにある「未決」は試作のための仮置きであり、勝手に確定扱いにしない。
- C++移行中のブランチ運用と [AGENTS.md](../AGENTS.md) を守り、移行中のロジック変更や別人の作業への干渉を避ける。
- pixelFXは参考にし、独自表現で制作する。試作は実際のGodot画面のGIFで確認する。
- ULTの最終仕様が決まった段階で docs/spec.md、英雄データ・C++挙動・描画・必要なテストの整合を取る。
- この引き継ぎは一時文書。ULTの作業が終わったら handoff/ とともに削除する。
