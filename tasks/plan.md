# ヒュドラ再設計の実装計画

**状態：承認済み。実装中。既存テスト失敗は別課題として扱う。** 実装の目的・検証・作業境界は [SPEC.md](../SPEC.md)、個別仕様の正は [ヒュドラ専用仕様](../docs/game/hydra.md)。本書は実装順・依存関係・受け入れ条件を定義し、未決のゲーム仕様は「承認待ちの提案」として区別する。[タスク一覧](todo.md) の対象はヒュドラ再設計だけとする。

## 対象と到達点

初回実装では、試遊シーンで中央を攻める合体形態から分離形態、不死の蛇の撃破、羅針盤の解放まで一戦を通せるようにする。分離後の通常の立ち回りは仮実装とする。ユーザーの試遊と立ち回り調整は今回の実装完了後の別作業として [タスク一覧の保留項目](todo.md#after-implementation) に残す。分離蛇の体全体のうねり、直進・曲線移動・旋回・被弾のモーションとゲーム中の自然な接続は初回実装に含める。通常10技、コンボ3種、大技5種、位置と欠員へ対応するBehaviorTree、アニメーション、ピクセルアート調のリッチなシェーダー演出を含む。

正式な格子5配置は配置案の受領待ち。今回の実装対象は仕組みと差替可能な仮1配置までとし、正式5配置は受領・レビュー後に追加タスクとして扱う。通常ステージへの出現変更、他のボス、demo、性能改善専任作業、共通獲得演出そのものの再制作、mainへの統合・push・公開は対象外。

分離後の大技の初期試遊目安は、連続飛びかかりのクールダウンを約15秒、格子ビームを約30秒とする。これは発動を強制する周期ではなく、使用可能になるまでの待ち時間の目安。実装時に`.tres`へ置き、以後はデータを数値の正とする。コンボの共通間隔の値は未決。

HP、距離、速度、再使用時間、予告・硬直時間などは、承認した規則に従う試遊用の調整値として`.tres`へ置く。未合意の値を確定バランスとして扱わない。

仮実装にできるのは移動・間合い・選択の調整であり、技の追加、形態進行の変更、特別な無敵条件の追加は範囲に含めない。今回の完了条件は一戦分の実装・検証・受け渡しとし、ユーザー試遊やその結果による調整の完了を含めない。

各攻撃の条件表は、開始できる形態・距離・向き、参加首と必要状態、狙い固定、割込み、終了後の各首、ほかの首の行動、再使用待ち、出せない場合の次の行動をそろえる。本体防衛より大技後の攻めどき・全首ダウン・形態移行を優先する構成を提案する。

## 各タスクの共通完了条件

- 期待する結果の失敗テストを先に実行し、最小実装後に成功を確かめる。仕様置換が必要な旧テストは、理由を明確にして同じ縦切りで更新する。
- 対象のBT選択・予告・判定・硬直・中断・演出を一緒に確認する。追加する攻撃を強制発動だけで完成扱いにしない。
- 新しいタイムラインとVFXは世界時間へ同期し、実ダメージのない命中エフェクトを作らない。Headlessの成功と描画品質の確認を区別する。
- 1タスクは主に3〜5ファイルを目安とする。表にあるパスは候補で、共有ファイルをすべて毎回触る指定ではない。大きく超える場合は、着手前にさらに遊べる縦切りへ分割する。
- 敵一覧の実装状況と必要な仕様・編集手順を同じ変更で更新する。調整値を文書へ転記しない。
- 実装時は対象ケース、Godot読み込み、影響する既存回帰を実行する。全体検証は下記の範囲を使い、失敗した基準状態を自分の変更による回帰と混同しない。
- 承認済みの実装段階では自分の変更だけを1タスク1コミットにする。計画作成段階ではコミットしない。未完のタスクを完了にせず、main・他作業・生成画像を巻き込まない。

## 検証方法

この計画作成中にゲーム・ゲームテストは実行しない。以下は実装承認後の検証手順。

1. 編集前に本番テストの対象一覧と起動方法を確定し、基準状態を実行する。`res://tests/*.tscn`の自動検証シーンと`check_rules.gd`を対象にし、`screen_capture`等の補助シーンは用途を確認して分ける。demoのテストは対象外。
2. 各タスクで独立した実験セッションと固定seedを使い、失敗→成功を記録する。新規ケースは`tests/hydra_*.gd`と対応シーンを基本とし、無制限の自動プレイを行わない。
3. 読み込み確認は`load_all.tscn`とGodotのインポートを使う。専用の本番配布ビルドは未設定なので、配布ビルド成功とは報告しない。
4. 描画付きの`hydra_trial.tscn`で短い画面確認をする。シェーダーの見た目・予告と危険範囲・反撃の成立は実画面で確認する。

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path speed --editor --import --quit
/Applications/Godot.app/Contents/MacOS/Godot --headless --path speed res://tests/load_all.tscn
/Applications/Godot.app/Contents/MacOS/Godot --headless --path speed --script res://tests/check_rules.gd
/Applications/Godot.app/Contents/MacOS/Godot --headless --path speed res://tests/hydra_ai.tscn

/Applications/Godot.app/Contents/MacOS/Godot --path speed res://gyms/hydra_trial.tscn
python3 tools/check_docs.py
git diff --check
```

実験場の`lab_core`・`lab_director`・`lab_replay`、攻撃枠の`attack_priority`・`clip_attack_priority`等も影響範囲に含め、全体検証では残る本番の自動検証シーンを実行する。既存の旧Hydra検証は仕様置換タスクと同時に更新し、理由なくスキップして成功扱いにしない。コマンドの終了値に加え、ログのFAILと読み込みエラーを確認する。図形・素材・シェーダーだけの変更では、振る舞いを再現するだけのテストを増やさず、読み込みと実画面を検証する。

### P1：中央を攻める経路を成立させる
<a id="h01"></a>

#### H01：中央の被弾から首の増加までをつなぐ

試遊シーンで中央へ直接攻撃し、HP閾値による無敵・増加アニメーションを経て戦闘へ戻る一本道を作る。中央瓦礫のHPと最終勝利を分離する。

**依存：** H00。 **規模：** M。

**受け入れ条件**

- [x] 上部の大ゲージに中央HP、頭付近に個別HPを表示する。体当たり・武器による中央への実ダメージで、承認済みの首構成へ一度ずつ進む。超過ダメージを持ち越し、複数閾値を越える際の演出順序も条件表どおりになる。
- [x] 無敵中の被弾と攻撃開始を止め、増加のアニメーション終了後に復帰する。増加時は既存首も全回復し、ダウンから復帰する。
- [x] 中央破壊は分離への移行要求になり、最終撃破・報酬・クリアを発火させない。分離未接続の間は試遊内で移行待機に入る。

**検証：** RED：閾値境界・過剰ダメージ・無敵中被弾・中央破壊時の勝利通知を再現。GREEN後に試遊で増加を確認する。 共通の読み込み・文書確認も適用する。

**変更候補：** hydra_boss.gd、hydra.tres、combat_manager.gd／boss_manager.gdの必要最小限の共通接続、tests/hydra_progression.*。Godot内のパスは`speed/`基準。

**受け入れ条件**

- [x] 全首ダウンは同じ更新の再生より先に成立し、保証されたチャンスタイムを通して中央を攻められる。

**検証：** RED：全滅と再生期限の同時到達、連続撃破、行再利用、火のケース。GREEN後に頭を順に倒して中央をなぞる。 共通の読み込み・文書確認も適用する。

### P2：首の形状と3本の大技を先に検証する
<a id="h03"></a>

#### H03：突き噛みを位置判断から反撃まで作る

通常の突き噛みを、首のBTによる選択から溜め・狙い固定・掃引判定・停止・復帰まで完成させる。以降の通常技もこの経路を拡張する。

## リスクと対処

| リスク | 対処 |
|---|---|
| 中央破壊が共通勝利を先に発火する | H01でダメージから最終勝利までの接続を分け、中央破壊単体で報酬が出ない回帰を先に置く |
| 固定根元から前方3本へ届かない、首が胴体を貫く | H04を早期の成立判定に置く。射程の数値を伸ばして隠さず、根元と経路を描画・幾何の両面で確認する |
| 通常技を増やしてもランダムにしか出せない | 各技で首BTの開始条件と代替行動を完成させる。H24は仕上げの総合確認とし、AI全体の後付け工程にしない |
| 蛇の見た目だけが揺れ、移動は直線追跡やその場回転になる | H19aで曲線移動と体の動きを連動させ、実際の戦闘中に旋回・被弾・攻撃との接続を描画確認する |
| 分離時の立ち回りを事前に決め切ろうとして止まる | H19で決定済み制約を満たす仮の動きを作る。ユーザー試遊と調整は今回完了後の別作業へ残し、今回の実装完了条件に含めない |
| 格子が画面比率や欠員で通れなくなる | 正規化した配置からワールド座標へ変換し、機体半径と経路長を含めて検証する。不成立なら通常行動へ戻る |
| 所有する頭が消えて演出や予約が漏れる | 予約・行とID・タイムライン・演出の終了を各技で検証し、リセットと形態移行でも同じ解放経路を通す |
| 既存回帰が旧仕様を期待し続ける | 基準結果を記録し、各機能の仕様置換時に該当検証を更新する。非Hydraケースを削って通さない |
| エフェクトを後回しにして仮図形のまま完成にする | 各攻撃タスクにピクセルシェーダー・アニメーション・実画面確認を含める |
| 関連外の未コミット変更と混在する | H00で帰属を照合し、明示した対象だけをコミットする。生成画像や他作業を退避・削除・追加しない |
| 共通勝利・獲得演出と競合する | 既存の`boss_dead`からの接続を使い、共通演出の内容は書き換えず必要な接続点だけ調整する |
