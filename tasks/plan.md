# ステージ1・5 実装計画

自動実装承認済み。[作業一覧](todo.md) の順序で実装・テスト・コミットを行う。[SPEC](../SPEC.md) と各ボス・ステージ文書を要件の正本とする。構図・ポーズの完成を待たず仮表示で進め、提供後に差し替える。別セッションのポーズ案は採用しない。

## 目的と完成ライン

両ステージの道中を仮タイムラインで遊べ、一角獣・竜の全技、行動判断、演出、決着が本番と編集用試遊で動く状態にする。冒頭とチュートリアルも接続する。仮素材・仮調整値と正式完成を区別する。ピネウスの救出・ウルトは対象外。

## 実装の順序と区切り

1. **一角獣を一戦として仕上げる（00〜05）**。全技の既存動作を確認し、移動・予告・命中・表示・終了を技ごとに仕上げる。ステージ1の6山からボスへ接続する。
2. **竜を早期に試遊できるようにする（06〜09）**。噛みつき一技と仮本体を実験場で動かし、フロー・編集・生成へつなぐ。HP閾値・多重命中のリスクを技の量産前に確認する。
3. **竜の技を一技ずつ完成させる（10〜21）**。各タスクはパラメータ→選択→予告→判定と表示→終了/中断→再読込までを扱う。全技のロジックだけを先に作って演出を最後へ回さない。
4. **決着まで遊べる一戦にする（22〜25）**。核解放、合体、自由描画、固定フィニッシュ、共通保存へ接続し、技同士の遷移を確認する。
5. **ステージ5の道中と登場を接続（26〜29）**。合意済みの育成・雑魚・カラス・時間配分を使う。山の編成の最終案はチェックポイントで確認し、未決を無断で確定しない。
6. **冒頭と操作導入を完成（30〜32）**。タイトルから旅立ちまで、既存の再視聴・スキップ・セーブの扱いを保って確認する。

各フェーズ内にも2〜3タスクごとの確認点をtodoに置く。確認では、動く成果、編集後の反映、未解決事項を提示する。

## 編集・生成・実行時の責務

- 技の数値・条件・フローは既存Resource、編成はシーン、ステージはStageDefを編集元にする。固定画像・形状・技の解析結果は正規の生成経路へ渡す。
- `.content/` とカタログ生成物を手修正しない。竜の新資源は生成対象・依存一覧・欠落検出・形式の版・配布参照まで追う。
- 本番はSessionの資源ScopeとBossSystemが所有する。ピカロ、弾、亀裂、演出は所有者と取消時の解放を定める。HP移行で残す弾と破棄するビーム等を区別する。
- 編集用プレビューは明示的な生成・新しい試遊へ渡す。既存ランの参照を差し替えて壊さない。
- 入力切替、勝利通知、敵表の行ID、画面と世界座標は既存の共通経路を使う。

## 保留・確認する点

- 構図・ポージングは仮表示で進める。後日の正式差し替えでは判定、遮蔽、縦横比も再確認する。
- 山の具体的な強敵編成は会話の直近案がある一方、正本では未決。26でその表を提示して確認する。時間配分・育成構成・成長方針を再質問しない。
- 技の照準固定時点・当たりの意味など未決の挙動は該当タスク着手時にまとめて相談する。秒数・速度等の調整値を仮設定できることと、挙動を決めることを混同しない。
- ピネウスは制作しない。複製数を吸収量で増やす案も採用しない。
- 通常敵をボス中にどう出すか、HP0時の残留物等の未決は該当接続点で確認する。ドキュメントにある規則は再質問しない。

## 検証と境界

検証コマンドは [SPECの開発コマンド](../SPEC.md#5-開発コマンド) を使う。実装段階で、正規生成・読み込み→短い手動試遊→保存して再読込を行う。自動テスト・長時間自動プレイは依頼時だけ。人間による通常開始の試遊で成長を確認し、途中再生のXPを通常成長の結果に混ぜない。

計画作成後の自動実装承認に従い、Godot起動・ビルド・自動テスト・実装コード変更・タスク単位のコミットを行う。pushは別途承認を得る。元の作業ツリーと未保存エディターを保護する。共有タスク一覧は更新しない。

指定された `tasks/plan.md`・`tasks/todo.md` はこの個別セッションの計画であり、共有タスク一覧とは別。文書規定と `tools/check_docs.py` は、この2ファイルに限って配置を認める。その他の作業文書の禁止を維持し、許可範囲と拒否範囲を回帰テストで確認する。
